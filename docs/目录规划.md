# Kunlun 1.1.1 简化目录与配置规划

本文定义 `1.1.1` 及后续版本的目录基线。安装根目录默认为 `/opt/Kunlun`，也可在首次安装时通过 `--root` 指定；下文统一写作 `<KUNLUN_ROOT>`。它取代 `1.1.0` 使用的 `packages/releases/current/state/config/kunlun.env` 模型。

> 当前是目标设计。现有 Compose 和脚本仍包含旧目录引用，必须完成代码改造和全新虚拟机复验后，才能制作正式 `1.1.1` 包。

## 1. 设计原则

- 中间件只初始化一次，后续应用升级默认不替换中间件镜像和 Compose。
- MySQL、Redis、RabbitMQ、MinIO 分别保存镜像 tar、持久化数据和备份。
- 应用镜像 tar 按应用版本保留，中间件不跟随应用版本复制。
- 运行中的 Compose 只有两份，路径固定，不通过软链接切换。
- 不再保留离线包解压副本和 release 副本两套相同文件。
- 不再使用运行时 `.env`；固定参数和站点凭据直接写入 Compose。
- 数据库初始化和升级脚本与应用版本绑定，但数据库数据仍属于 MySQL 持久化目录。

## 3. 哪些目录按中间件分开

| 组件 | 镜像 tar | 持久化数据 | 主要备份 |
|---|---|---|---|
| MySQL | `middleware/mysql/image` | `middleware/mysql/data` | 逻辑 SQL + 停机数据副本 |
| Redis | `middleware/redis/image` | `middleware/redis/data` | RDB/AOF + 停机数据副本 |
| RabbitMQ | `middleware/rabbitmq/image` | `middleware/rabbitmq/data` | definitions + 停机数据副本 |
| MinIO | `middleware/minio/image` | `middleware/minio/data` | 对象镜像或停机数据副本 |

四个中间件只在目录和数据上分开，运行编排仍是一份 `compose.middleware.yml`。这样既能独立备份、恢复和排障，又不增加四套 Compose 的运维负担。

## 4. 真正生效的配置

### 4.1 中间件

```text
<KUNLUN_ROOT>/middleware/compose.middleware.yml
```

该文件直接保存：

- MySQL、Redis、RabbitMQ、MinIO 固定镜像标签；
- `<KUNLUN_ROOT>/middleware/.../data` 绝对挂载路径；
- 数据库名、账号以及各中间件独立密码；
- RabbitMQ vhost、MinIO bucket；
- 管理端口和健康检查；
- 外部网络 `kunlun-net`。

### 4.2 应用

```text
<KUNLUN_ROOT>/application/compose.app.yml
```

该文件直接保存：

- 当前 backend/frontend 镜像标签；
- 前端对外端口；
- backend 的中间件 DNS 地址；
- 与 middleware Compose 相同的各组件业务账号和密码副本；
- Java 内存和健康检查。

### 4.3 MySQL 和数据库脚本

- `middleware/mysql/conf.d` 是 MySQL 运行配置，当前没有需求可以保持空目录。
- `middleware/mysql/init` 只在 MySQL data 为空时由官方 entrypoint 自动读取。
- `database/init` 是交付源；首次部署时按需要复制到 `middleware/mysql/init`。
- `database/migrations/<应用版本>` 只在应用升级窗口手工执行，不能挂载为每次启动自动运行。

## 5. 不再保留的目录

| 旧目录 | 原用途 | 取消原因 |
|---|---|---|
| `packages/<版本>` | 保存完整离线包解压副本 | 与运行目录和镜像 tar 重复，占空间 |
| `releases/<版本>` | 保存不可变运行版本 | 中间件不随应用升级，无需整套复制 |
| `current` | 软链接切换 release | 当前 app Compose 使用固定路径即可 |
| `state` | 自动化脚本状态 | V1 手工版不需要；V2 日后仅记录日志 |
| `config/kunlun.env` | Compose 参数和密码 | 固定参数与密码直接写入 Compose |

当前应用版本由以下命令直接确定，不再维护额外状态文件：

```bash
docker compose -f <KUNLUN_ROOT>/application/compose.app.yml config --images
```

## 6. 权限基线

| 路径 | 权限 | 说明 |
|---|---:|---|
| `<KUNLUN_ROOT>` | 0755 root:root | 总入口 |
| `docker/install` | 0700 root:root | 安装介质 |
| `docker/data` | 0710 root:root | Docker data-root，按 daemon 要求校准 |
| 两份 Compose | 0600 root:root | 含明文凭据 |
| 四个 `image` 目录 | 0700 root:root | 离线镜像交付物 |
| MySQL `conf.d`、`init` | 0755 root:root | 容器内 mysql 用户必须可遍历和读取 |
| 四个 `data` 目录 | 0750 | 属主按镜像实际 UID/GID 设置 |
| `database/migrations` | 0700 root:root | 可能包含业务结构信息 |
| `backups` | 0700 root:root | 含业务数据和敏感 Compose 快照 |
| `logs` | 0750 root:root | 日志禁止打印密码 |
| `tmp` | 0700 root:root | 使用后清理 |

## 7. 离线包与目标目录的关系

完整初始化包应先解压到安装根目录之外的受控介质目录，再通过 `install-bootstrap.sh --root <KUNLUN_ROOT>` 校验并安装。安装完成后，镜像 tar 会保存在各中间件 `image` 目录和 `application/images/<版本>`；外层解压副本可按审计要求清理。

因此目标机不再同时保存“压缩包、packages 副本、release 副本”三套相同内容。外层压缩包是否保留由磁盘和审计要求决定；如果保留，必须以 `0600` 存放到受控介质，而不是重新引入长期 `packages` 目录。

## 8. 版本边界

### 完整初始化版本 1.1.1

包含 Docker、固定中间件和应用，是新机器的安装基线。

### 应用更新版本 1.1.2 及以后

只增加：

- `application/images/<版本>`；
- 新 `application/compose.app.yml`；
- `database/migrations/<版本>`；
- 相应备份和升级日志。

默认不改变：

- `middleware/compose.middleware.yml`；
- 四个中间件镜像 tar；
- 四个中间件 data；
- Docker Engine 和 data-root。
