# Kunlun 应用与数据库手工升级

本文用于在已经完成 `1.1.1` 首次部署的服务器上安装 `1.1.2` 及以后应用版本。默认中间件镜像、`compose.middleware.yml` 和四个中间件数据目录都不变。

## 1. 更新包边界

应用更新包命名：

```text
kunlun-app-update-1.1.2-linux-amd64.tar.gz
kunlun-app-update-1.1.2-linux-amd64.tar.gz.sha256
```

包内结构：

```text
kunlun-app-update-1.1.2-linux-amd64/
├── manifest.env
├── SHA256SUMS
├── application/
│   ├── compose.app.yml
│   └── images/1.1.2/
│       ├── offline-demo-backend-1.1.2-linux-amd64.tar
│       ├── offline-demo-backend-1.1.2-linux-amd64.tar.sha256
│       ├── offline-demo-frontend-1.1.2-linux-amd64.tar
│       └── offline-demo-frontend-1.1.2-linux-amd64.tar.sha256
├── database/migrations/1.1.2/
│   ├── precheck.sql
│   ├── up.sql
│   ├── verify.sql
│   └── rollback.sql
└── docs/
```

没有数据库变化时，manifest 必须明确记录 `DB_MIGRATION_REQUIRED=false`，迁移目录可以为空。禁止用“没有提供 SQL”隐含表示没有数据库变化。

更新包不得包含：

- Docker 安装介质；
- MySQL、Redis、RabbitMQ、MinIO 镜像 tar；
- `compose.middleware.yml`；
- 任何在线 data 目录。

## 2. 更新前门禁

确认当前应用镜像：

```bash
docker compose --project-name kunlun-app \
  -f /opt/Kunlun/application/compose.app.yml \
  config --images
```

确认两套项目健康：

```bash
docker compose --project-name kunlun-middleware \
  -f /opt/Kunlun/middleware/compose.middleware.yml ps

docker compose --project-name kunlun-app \
  -f /opt/Kunlun/application/compose.app.yml ps

bash /opt/Kunlun/scripts/check-middleware.sh
```

确认空间：

```bash
df -h /opt/Kunlun
docker system df
```

以下任一情况禁止升级：

- 中间件或当前应用不健康；
- 更新包来源、版本或 SHA256 不明确；
- 新 `compose.app.yml` 修改了中间件地址或账号密码；
- 数据库有变化但没有迁移说明、备份和验证 SQL；
- 磁盘不足以同时保存旧镜像、新镜像和数据库备份。

## 3. 校验更新包

```bash
cd /opt/Kunlun/tmp
sha256sum -c kunlun-app-update-1.1.2-linux-amd64.tar.gz.sha256
chmod 0600 kunlun-app-update-1.1.2-linux-amd64.tar.gz

tar -xzf kunlun-app-update-1.1.2-linux-amd64.tar.gz
cd kunlun-app-update-1.1.2-linux-amd64
sha256sum -c SHA256SUMS
```

校验新 Compose，但不展开内容：

```bash
docker compose -f application/compose.app.yml config --quiet
```

必须使用不显示值的检查脚本逐项比较新 `compose.app.yml` 与在线 `compose.middleware.yml` 的 MySQL、Redis、RabbitMQ、MinIO 业务账号密码。任一项不一致就停止，不能在普通应用升级中顺便修改中间件密码。

## 4. 创建升级备份

生成时间戳：

```bash
timestamp="$(date '+%Y%m%dT%H%M%S%z')"
install -d -m 0700 "/opt/Kunlun/backups/application/$timestamp"
install -d -m 0700 "/opt/Kunlun/backups/mysql/$timestamp"
```

备份当前应用 Compose：

```bash
install -m 0600 \
  /opt/Kunlun/application/compose.app.yml \
  "/opt/Kunlun/backups/application/$timestamp/compose.app.yml"
```

保存当前应用镜像 ID：

```bash
docker compose --project-name kunlun-app \
  -f /opt/Kunlun/application/compose.app.yml \
  images --format json \
  >"/opt/Kunlun/backups/application/$timestamp/images.json"
chmod 0600 "/opt/Kunlun/backups/application/$timestamp/images.json"
```

导出 MySQL：

```bash
docker compose --project-name kunlun-middleware \
  -f /opt/Kunlun/middleware/compose.middleware.yml \
  exec -T mysql sh -ec \
  'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump -uroot --single-transaction --routines --events --triggers --all-databases' \
  >"/opt/Kunlun/backups/mysql/$timestamp/all-databases.sql"

chmod 0600 "/opt/Kunlun/backups/mysql/$timestamp/all-databases.sql"
sha256sum "/opt/Kunlun/backups/mysql/$timestamp/all-databases.sql" \
  >"/opt/Kunlun/backups/mysql/$timestamp/SHA256SUMS"
```

备份失败禁止继续。

## 5. 安装新镜像和迁移文件

```bash
install -d -m 0700 /opt/Kunlun/application/images/1.1.2
cp -a application/images/1.1.2/. /opt/Kunlun/application/images/1.1.2/

install -d -m 0700 /opt/Kunlun/database/migrations/1.1.2
cp -a database/migrations/1.1.2/. /opt/Kunlun/database/migrations/1.1.2/

docker load -i /opt/Kunlun/application/images/1.1.2/offline-demo-backend-1.1.2-linux-amd64.tar
docker load -i /opt/Kunlun/application/images/1.1.2/offline-demo-frontend-1.1.2-linux-amd64.tar
```

核对镜像平台：

```bash
docker image inspect --format '{{.RepoTags}} {{.Os}}/{{.Architecture}} {{.Id}}' \
  offline-demo-backend:1.1.2 \
  offline-demo-frontend:1.1.2
```

## 6. 执行数据库迁移

如果 `DB_MIGRATION_REQUIRED=false`，跳过本节并在升级日志中明确记录。

有数据库变化时先停止应用，保持中间件运行：

```bash
docker compose --project-name kunlun-app \
  -f /opt/Kunlun/application/compose.app.yml stop
```

执行预检：

```bash
docker compose --project-name kunlun-middleware \
  -f /opt/Kunlun/middleware/compose.middleware.yml \
  exec -T mysql sh -ec \
  'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot "$MYSQL_DATABASE"' \
  </opt/Kunlun/database/migrations/1.1.2/precheck.sql
```

执行升级：

```bash
docker compose --project-name kunlun-middleware \
  -f /opt/Kunlun/middleware/compose.middleware.yml \
  exec -T mysql sh -ec \
  'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot "$MYSQL_DATABASE"' \
  </opt/Kunlun/database/migrations/1.1.2/up.sql
```

执行数据库验证：

```bash
docker compose --project-name kunlun-middleware \
  -f /opt/Kunlun/middleware/compose.middleware.yml \
  exec -T mysql sh -ec \
  'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot "$MYSQL_DATABASE"' \
  </opt/Kunlun/database/migrations/1.1.2/verify.sql
```

迁移 SQL 应尽量使用事务和可重复检查。破坏性变更，例如直接删除列或表，必须拆成跨版本兼容迁移，不能与新应用一次性强耦合上线。

## 7. 切换应用版本

只有数据库迁移成功后才安装新应用 Compose：

```bash
install -m 0600 application/compose.app.yml /opt/Kunlun/application/compose.app.yml

docker compose --project-name kunlun-app \
  -f /opt/Kunlun/application/compose.app.yml \
  config --quiet

docker compose --project-name kunlun-app \
  -f /opt/Kunlun/application/compose.app.yml \
  up -d --wait --wait-timeout 360
```

该操作只重建 backend/frontend，不执行 middleware Compose。

## 8. 升级验收

```bash
docker compose --project-name kunlun-app \
  -f /opt/Kunlun/application/compose.app.yml ps

docker compose --project-name kunlun-app \
  -f /opt/Kunlun/application/compose.app.yml \
  exec -T frontend wget -q -O - http://127.0.0.1/api/health/all
```

同时检查：

- 顶层 `"ok":true`；
- 两个应用容器使用 `1.1.2` 镜像；
- 四个中间件仍是原镜像和原容器数据；
- 新功能和数据库字段通过业务验收；
- 日志没有持续异常。

## 9. 失败处理与回退

### 数据库没有变化

恢复旧 Compose 并重建应用：

```bash
install -m 0600 \
  "/opt/Kunlun/backups/application/$timestamp/compose.app.yml" \
  /opt/Kunlun/application/compose.app.yml

docker compose --project-name kunlun-app \
  -f /opt/Kunlun/application/compose.app.yml \
  up -d --wait --wait-timeout 360
```

### 数据库已经变化

不能只切回旧镜像。只有满足以下条件之一才能回退：

- 新旧应用都兼容迁移后的数据库；
- 已验证 `rollback.sql` 可以安全执行；
- 停机恢复升级前 MySQL 备份。

禁止自动执行数据库回退。涉及数据恢复时必须停止应用、确认备份 SHA256，并按恢复 SOP 操作。

## 10. 清理规则

升级成功并完成观察期后：

- 保留当前和前一个应用版本镜像 tar；
- 保留升级前数据库备份；
- 清理 `/opt/Kunlun/tmp` 中的更新包解压目录；
- 不执行 `docker system prune -a`；
- 不删除四个中间件 data；
- 不删除仍可能用于回退的旧应用镜像。
