# V1 手工离线部署实测记录

> 历史文档：本文只记录 `1.1.0` 旧目录实测，包含当时的 `packages/releases/current/state/kunlun.env`。这些路径不再属于 `1.1.1` 目标方案，不能从本文复制命令部署新版本。新版本以 [目录规划](目录规划.md) 和 [V1 手工版](V1-手工版.md) 为准。

本文记录 2026-08-23 在恢复到初始快照的虚拟机上执行 `1.1.0` bootstrap 手工部署的实际结果。操作步骤仍以 [V1 手工版](V1-手工版.md) 为准；本文用于保存环境、交付物、结果、偏差和后续动作。

## 1. 验收结论

核心部署链路已经走通：外层和包内校验、Docker/Compose 离线安装、六个镜像分包导入、`/opt/Kunlun` 目录、双 Compose、四个中间件、前后端和业务健康检查均已在实际目标机完成。

本次实测同时发现并修复了 MySQL 配置目录权限缺陷。因此，哈希为 `c69c...` 的 `1.1.0` 压缩包只能作为本次验证候选包保存，不能作为最终黄金包继续分发。修复后的源文件必须使用新发布版本重新打包和复验，不能静默覆盖同版本、同文件名但哈希不同的旧包。

以下两项没有在现有会话输出中形成完成证据，仍标为待验收：

- 执行一次 `backup.sh` 并校验备份清单；
- 执行一次 `restore.sh`，确认只恢复到演练目录且不覆盖生产数据。

## 4. 已验证的运行模型

- MySQL、Redis、RabbitMQ、MinIO 由 `compose.middleware.yml` 管理。
- backend、frontend 由 `compose.app.yml` 管理。
- backend 通过 `mysql:3306`、`redis:6379`、`rabbitmq:5672` 和 `minio:9000` 访问中间件。
- MySQL 使用 `offline_demo` 和业务账号 `offline_app`，后端不使用 root。
- MySQL、Redis、RabbitMQ AMQP、MinIO API 和 backend 不映射宿主机端口。
- RabbitMQ 管理台和 MinIO 控制台仅绑定宿主机回环地址。
- 前端通过宿主机 80 端口提供访问，`/api/health/all` 用于完整业务验收。
- 本次 `1.1.0` 实测时，现场账号和密码保存在 `/opt/Kunlun/config/kunlun.env`，权限为 `root:root 0600`。
- 中间件数据保存在 `/opt/Kunlun/data`，release 切换不覆盖数据。

## 5. 实测问题和处理

### 5.1 Docker Hub 访问失败

构建机直连 Docker Hub 的 token 和镜像元数据请求超时。构建和拉取阶段通过已选定的镜像加速地址获取内容，随后恢复为交付所需的正式镜像标签。目标机部署全程使用本地 tar，Compose 配置为 `pull_policy: never`。

### 5.2 GitHub Compose 下载极慢

直接下载 Compose 二进制速度过低，且原命令的 `--max-time 900` 会在 15 分钟后中断。实测改为从 Docker 官方验证发布的 `docker/compose-bin:v5.4.0` 镜像提取 `/docker-compose`，再用 GitHub 发布的 SHA256 校验。

### 5.3 Windows Schannel 吊销服务不可达

下载 Compose 的 SHA256 时出现 `CRYPT_E_NO_REVOCATION_CHECK`。使用 `curl --ssl-revoke-best-effort` 仅在吊销列表分发点缺失或离线时放宽检查，没有使用 `--insecure`。参数语义见 [curl 官方手册](https://curl.se/docs/manpage.html)。

### 5.4 Windows PowerShell 中文路径乱码

`SHA256SUMS` 必须使用 UTF-8 无 BOM，因为包内含中文文档名。Windows PowerShell 5.1 读取时必须显式使用：

```powershell
Get-Content -LiteralPath $ChecksumPath -Encoding UTF8
```

未指定编码时出现的 `V1-鎵嬪伐...` 是读取乱码，不是包内文件损坏。

### 5.5 截断 tar 列表造成假失败

以下写法会让 `Select-Object` 在取得 20 行后关闭管道，导致 `tar` 收到断管并留下非零退出码：

```powershell
tar -tzf $ArchivePath | Select-Object -First 20
```

验收必须让 `tar` 完整读取：

```powershell
tar -tzf $ArchivePath | Out-Null
if ($LASTEXITCODE -ne 0) { throw '最终压缩包无法读取' }
```

### 5.6 MySQL `conf.d` 权限不足

首次启动时 MySQL 循环重启，日志为：

```text
mysqld: Can't read dir of '/etc/mysql/conf.d/' (OS errno 13 - Permission denied)
```

原因是宿主机目录被初始化为 `root:root 0750`，而 MySQL entrypoint 会切换为容器内 `mysql` 用户。实测临时修复为：

```bash
chmod 0755 /opt/Kunlun/config/mysql/conf.d
chmod 0755 /opt/Kunlun/data/mysql/init
```

项目源文件已改为创建 `0755` 目录，并把两个挂载设为只读。修复后需要用新发布版本重新生成离线包。

### 5.7 包内总手册相对链接多一层

本次组包把根目录的 `部署手册.md` 复制到了离线包的 `docs/` 下，但该文件的链接本来就是 `docs/V1-手工版.md` 形式，因此包内点击时会错误解析为 `docs/docs/...`。运行部署不受影响。下版改为把总手册放在离线包根目录，专题文档继续放在 `docs/`。

## 6. 密码和离线包决策

`1.1.0` 实测采用 `.env` 中的独立随机密码。实测完成后，业务方明确变更交付约定：四个中间件改为一套共享明文密码，账号和密码直接写入 Compose，离线 tar 同时携带该配置。

后续版本按以下规则执行：

- `compose.middleware.yml` 保存中间件初始化账号和共享密码；
- `compose.app.yml` 保存 backend 连接所需的相同凭据副本；
- `.env`、应用默认配置和脚本不再设置账号或密码；
- 两个独立 YAML 无法共享 anchor，构建时必须校验两份凭据完全一致；
- Compose 安装权限为 `root:root 0600`，备份中的 Compose 同样使用 `0600`；
- 含明文密码的 tar 是站点专用敏感包，禁止进入公共 Git、日志、普通制品库或跨站点复用。

这是业务方接受风险后的项目特定取舍，不是通用安全建议。共享密码会扩大单点泄露的影响范围；SHA256 只能校验完整性，不能隐藏密码。若后续安全要求提高，可迁移到 [Docker Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/) 并建立轮换、撤销和备份流程，参考 [OWASP Secrets Management](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)。

该变更不能回写或同名覆盖已经验证的 `1.1.0` 包。必须使用新发布版本重新组包；对已有 MySQL/RabbitMQ 数据也不能只替换 Compose，必须执行显式密码轮换。首次复验应使用全新数据目录或恢复后的初始虚拟机。
