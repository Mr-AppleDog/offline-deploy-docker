# V1：Kunlun 1.1.1 首次手工离线部署

本文用于在一台全新、无 Docker、无业务数据的 Kylin Linux V10 `x86_64` 服务器上手工部署 `1.1.1`。

> 实施状态：`1.1.1` 简化结构已经在 Kylin V10 `x86_64` 虚拟机完成核心手工部署，结果见 [1.1.1 实测记录](1.1.1-手工部署实测记录.md)。首次备份和恢复演练仍待完成；后续新增的一键初始化脚本必须使用独立交付修订包复验，不能覆盖本次已冻结的 tar。

## 1. 范围和停止条件

本次完整初始化包含：

- Docker Engine `29.7.0`；
- Docker Compose `v5.4.0`；
- MySQL `8.4.11`；
- Redis `8.2.8`；
- RabbitMQ `4.3.4-management`；
- MinIO `RELEASE.2025-07-18T21-56-31Z`；
- backend/frontend `1.1.1`。

出现以下任一情况立即停止，不继续启动应用：

- SHA256 校验失败；
- 目标机不是 `x86_64`；
- Docker Root Dir 不是 `/opt/Kunlun/docker/data`；
- 任一镜像不是 `linux/amd64`；
- 两份 Compose 凭据不一致；
- 任一中间件不是 `healthy`；
- 磁盘空间不足；
- 目标数据目录已经存在未知业务数据。

## 2. 完整初始化包结构

```text
kunlun-bootstrap-1.1.1-linux-amd64/
├── manifest.env
├── images.txt
├── SHA256SUMS
├── docker/install/
├── middleware/
│   ├── compose.middleware.yml
│   ├── mysql/image/<tar + sha256>
│   ├── redis/image/<tar + sha256>
│   ├── rabbitmq/image/<tar + sha256>
│   └── minio/image/<tar + sha256>
├── application/
│   ├── compose.app.yml
│   └── images/1.1.1/<backend/frontend tar + sha256>
├── database/init/
├── scripts/
└── docs/
```

外层交付文件：

```text
kunlun-bootstrap-1.1.1-linux-amd64.tar.gz
kunlun-bootstrap-1.1.1-linux-amd64.tar.gz.sha256
```

两份 Compose 包含站点明文凭据，因此外层 tar 是敏感材料，不能上传到公共制品库。

## 3. 构建机准备

在 Windows PowerShell 中进入项目根目录：

```powershell
cd D:\my\offline-deploy-docker

$AppVersion = '1.1.1'
$Platform = 'linux/amd64'
$DockerVersion = '29.7.0'
$ComposeVersion = 'v5.4.0'
```

检查本机 Docker：

```powershell
docker info --format '{{.OSType}}/{{.Architecture}}'
docker buildx version
docker compose version
```

构建 backend/frontend：

```powershell
docker buildx build --platform $Platform --pull --load `
  -t "offline-demo-backend:$AppVersion" .\backend

docker buildx build --platform $Platform --pull --load `
  -t "offline-demo-frontend:$AppVersion" .\frontend
```

构建机访问 Docker Hub 受限时，可以使用经过确认的镜像代理完成拉取，但导出前必须恢复正式镜像标签。目标机 Compose 只引用正式标签。

## 4. 构建机镜像门禁

需要交付的六个镜像：

```powershell
$RuntimeImages = @(
  'mysql:8.4.11',
  'redis:8.2.8',
  'rabbitmq:4.3.4-management',
  'minio/minio:RELEASE.2025-07-18T21-56-31Z',
  'offline-demo-backend:1.1.1',
  'offline-demo-frontend:1.1.1'
)
```

逐个确认平台：

```powershell
$RuntimeImages | ForEach-Object {
  docker image inspect --format "$_ -> {{.Os}}/{{.Architecture}} {{.Id}}" $_
}
```

六个镜像必须全部是 `linux/amd64`。

## 5. Compose 构建门禁

新的两份 Compose 必须已经满足：

- 不引用 `${...}` 运行时变量；
- 不依赖 `.env` 或 `--env-file`；
- 使用固定镜像标签和 `/opt/Kunlun` 绝对路径；
- 使用 `pull_policy: never`；
- 各中间件账号和独立密码由 Web 平台按站点写入 Compose；
- 两份 Compose 中的业务账号和密码一致。

只做解析校验，不输出展开结果，避免密码进入终端：

```powershell
docker compose -f .\deploy\compose.middleware.yml config --quiet
docker compose -f .\deploy\compose.app.yml config --quiet
```

禁止执行会把完整环境变量展开到日志的命令：

```text
docker compose config
docker inspect <容器>
```

## 6. 生成六个独立镜像 tar

先创建全新的包目录，禁止覆盖同名输出：

```powershell
$KitName = "kunlun-bootstrap-$AppVersion-linux-amd64"
$KitRoot = Join-Path $PWD "dist\$KitName"
$ArchivePath = "$KitRoot.tar.gz"

if (Test-Path -LiteralPath $KitRoot) { throw "目录已经存在：$KitRoot" }
if (Test-Path -LiteralPath $ArchivePath) { throw "压缩包已经存在：$ArchivePath" }

$Directories = @(
  'docker\install',
  'middleware\mysql\image',
  'middleware\redis\image',
  'middleware\rabbitmq\image',
  'middleware\minio\image',
  "application\images\$AppVersion",
  'database\init',
  'scripts',
  'docs'
)

$Directories | ForEach-Object {
  New-Item -ItemType Directory -Force (Join-Path $KitRoot $_) | Out-Null
}
```

复制已经按简化结构改造完成的 Compose、脚本、文档和 Docker 安装介质：

```powershell
Copy-Item .\deploy\compose.middleware.yml "$KitRoot\middleware\compose.middleware.yml"
Copy-Item .\deploy\compose.app.yml "$KitRoot\application\compose.app.yml"
Copy-Item .\deploy\scripts\*.sh "$KitRoot\scripts\"
Copy-Item .\docs\*.md "$KitRoot\docs\"
Copy-Item .\README.md, .\部署手册.md $KitRoot

# 该目录必须提前准备并完成发布方 SHA256 校验。
$DockerMediaRoot = Join-Path $PWD 'artifacts\docker'
if (-not (Test-Path -LiteralPath $DockerMediaRoot)) {
  throw "缺少 Docker 离线介质：$DockerMediaRoot"
}
Copy-Item "$DockerMediaRoot\*" "$KitRoot\docker\install\"
```

每个组件独立执行 `docker save`：

```powershell
docker save -o "$KitRoot\middleware\mysql\image\mysql-8.4.11-linux-amd64.tar" mysql:8.4.11
docker save -o "$KitRoot\middleware\redis\image\redis-8.2.8-linux-amd64.tar" redis:8.2.8
docker save -o "$KitRoot\middleware\rabbitmq\image\rabbitmq-4.3.4-management-linux-amd64.tar" rabbitmq:4.3.4-management
docker save -o "$KitRoot\middleware\minio\image\minio-RELEASE.2025-07-18T21-56-31Z-linux-amd64.tar" minio/minio:RELEASE.2025-07-18T21-56-31Z
docker save -o "$KitRoot\application\images\1.1.1\offline-demo-backend-1.1.1-linux-amd64.tar" offline-demo-backend:1.1.1
docker save -o "$KitRoot\application\images\1.1.1\offline-demo-frontend-1.1.1-linux-amd64.tar" offline-demo-frontend:1.1.1
```

为每个镜像 tar 生成同目录 `.sha256`：

```powershell
$ImageTars = Get-ChildItem -LiteralPath $KitRoot -Filter '*.tar' -File -Recurse
if ($ImageTars.Count -ne 6) { throw "镜像 tar 数量错误：$($ImageTars.Count)" }

foreach ($TarFile in $ImageTars) {
  $Hash = (Get-FileHash -LiteralPath $TarFile.FullName -Algorithm SHA256).Hash.ToLowerInvariant()
  [IO.File]::WriteAllText(
    "$($TarFile.FullName).sha256",
    "$Hash  $($TarFile.Name)`n",
    [Text.Encoding]::ASCII
  )
}
```

生成 manifest：

```powershell
$Manifest = @(
  'PACKAGE_TYPE=bootstrap',
  "APP_VERSION=$AppVersion",
  "TARGET_PLATFORM=$Platform",
  'MIDDLEWARE_POLICY=fixed',
  'DB_MIGRATION_TOOL=none',
  'CREDENTIAL_MODE=embedded-compose'
)
[IO.File]::WriteAllText(
  "$KitRoot\manifest.env",
  (($Manifest -join "`n") + "`n"),
  [Text.Encoding]::ASCII
)
```

生成 `images.txt`，记录六个镜像的正式标签、完整 image ID、平台、tar 相对路径和 tar SHA256：

```powershell
$ImageRecords = @(
  @{ Image='mysql:8.4.11'; Tar='middleware/mysql/image/mysql-8.4.11-linux-amd64.tar' },
  @{ Image='redis:8.2.8'; Tar='middleware/redis/image/redis-8.2.8-linux-amd64.tar' },
  @{ Image='rabbitmq:4.3.4-management'; Tar='middleware/rabbitmq/image/rabbitmq-4.3.4-management-linux-amd64.tar' },
  @{ Image='minio/minio:RELEASE.2025-07-18T21-56-31Z'; Tar='middleware/minio/image/minio-RELEASE.2025-07-18T21-56-31Z-linux-amd64.tar' },
  @{ Image='offline-demo-backend:1.1.1'; Tar='application/images/1.1.1/offline-demo-backend-1.1.1-linux-amd64.tar' },
  @{ Image='offline-demo-frontend:1.1.1'; Tar='application/images/1.1.1/offline-demo-frontend-1.1.1-linux-amd64.tar' }
)

$ImageLines = foreach ($Record in $ImageRecords) {
  $Identity = docker image inspect --format '{{.Id}}|{{.Os}}/{{.Architecture}}' $Record.Image
  if ($LASTEXITCODE -ne 0) { throw "镜像检查失败：$($Record.Image)" }
  $TarPath = Join-Path $KitRoot $Record.Tar.Replace('/', '\')
  $TarHash = (Get-FileHash -LiteralPath $TarPath -Algorithm SHA256).Hash.ToLowerInvariant()
  "$($Record.Image)|$Identity|$($Record.Tar)|$TarHash"
}

[IO.File]::WriteAllText(
  "$KitRoot\images.txt",
  (($ImageLines -join "`n") + "`n"),
  [Text.Encoding]::ASCII
)
```

随后生成包根 `SHA256SUMS`，校验文件使用 UTF-8 无 BOM、LF 换行和相对路径：

```powershell
$ChecksumLines = Get-ChildItem -LiteralPath $KitRoot -File -Recurse |
  Where-Object { $_.Name -ne 'SHA256SUMS' } |
  Sort-Object FullName |
  ForEach-Object {
    $Hash = (Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256).Hash.ToLowerInvariant()
    $Relative = $_.FullName.Substring($KitRoot.Length + 1).Replace('\', '/')
    "$Hash  $Relative"
  }

[IO.File]::WriteAllText(
  "$KitRoot\SHA256SUMS",
  (($ChecksumLines -join "`n") + "`n"),
  [Text.UTF8Encoding]::new($false)
)
```

逐条在本机重新计算并验证 `SHA256SUMS` 后，再生成外层压缩包：

```powershell
tar -czf $ArchivePath -C (Split-Path $KitRoot) (Split-Path $KitRoot -Leaf)
if ($LASTEXITCODE -ne 0 -or -not (Test-Path -LiteralPath $ArchivePath)) {
  throw '离线包压缩失败'
}

$ArchiveHash = (Get-FileHash -LiteralPath $ArchivePath -Algorithm SHA256).Hash.ToLowerInvariant()
$ArchiveName = Split-Path $ArchivePath -Leaf
[IO.File]::WriteAllText(
  "$ArchivePath.sha256",
  "$ArchiveHash  $ArchiveName`n",
  [Text.Encoding]::ASCII
)
```

最终压缩后必须完整读取 tar，不能用截断管道判断成功：

```powershell
tar -tzf $ArchivePath | Out-Null
if ($LASTEXITCODE -ne 0) { throw '最终压缩包无法读取' }
```

## 7. 目标机预检

把两个外层文件上传到 `/opt/Kunlun/tmp`，然后执行：

```bash
uname -m
cat /etc/os-release
ps -p 1 -o comm=
command -v tar
command -v sha256sum
command -v systemctl
df -h /opt
```

要求：

- `uname -m` 为 `x86_64`；
- init 为 `systemd`；
- 有 `tar` 和 `sha256sum`；
- `/opt` 容量满足 Docker 镜像层、镜像 tar、在线数据、备份和至少 20% 余量。

检查端口：

```bash
conflicts="$(ss -H -lntp | grep -E ':(80|15672|9001)[[:space:]]' || true)"
if [ -n "$conflicts" ]; then
  echo '错误：部署端口已被占用'
  printf '%s\n' "$conflicts"
  exit 1
fi
```

## 10. 安装 Docker 和 Compose

如果目标机没有 Docker，先把包内 `docker/install` 复制到 `/opt/Kunlun/docker/install`，然后安装静态二进制和 systemd unit。必须在第一次 `docker load` 之前配置：

```json
{
  "data-root": "/opt/Kunlun/docker/data",
  "log-driver": "local",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  }
}
```

配置文件位置：

```text
/etc/docker/daemon.json
```

启动后验证：

```bash
docker info --format 'Server={{.ServerVersion}} Root={{.DockerRootDir}} OS={{.OSType}} Arch={{.Architecture}}'
docker compose version
```

预期 Root 必须为 `/opt/Kunlun/docker/data`。

## 13. 初始化数据目录权限

数据目录属主必须根据镜像内实际运行用户确定，不能统一使用 `root`，也禁止使用 `0777`。执行改造后的 `/opt/Kunlun/scripts/init-dirs.sh`，然后核对：

```bash
bash /opt/Kunlun/scripts/init-dirs.sh
find /opt/Kunlun/middleware -maxdepth 3 -type d -printf '%u:%g %m %p\n' | sort
```

MySQL 的 `conf.d` 和 `init` 必须为 `0755 root:root`，否则容器内 mysql 用户可能无法遍历。

## 17. 首次备份和恢复演练

部署验收后执行改造后的备份脚本：

```bash

```

备份必须分别落入 `/opt/Kunlun/backups/mysql`、`redis`、`rabbitmq`、`minio` 和 `application`，并生成 SHA256。两份 Compose 的备份权限必须为 `0600`。

恢复演练必须恢复到 `/opt/Kunlun/tmp/restore-test-*`，不能覆盖在线 data：

```bash
bash /opt/Kunlun/scripts/restore.sh --test <备份时间戳>
```

## 18. 完成记录

保存以下非敏感信息到部署日志：

- 外层包 SHA256；
- Docker/Compose 版本和 Docker Root Dir；
- 六个镜像标签、ID 和平台；
